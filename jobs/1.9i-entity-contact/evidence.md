# Entity pair contact evidence

`powershell -NoProfile -ExecutionPolicy Bypass -File jobs/1.9i-entity-contact/run-oracle.ps1` compiles `Oracle.java` against the staged server jar and libraries, executes Mojang `Entity.push(Entity)` once per row, writes `oracle.txt`, and compares every output velocity component by raw bits with the law. `run-mutant.ps1` temporarily makes the cutoff exclusive, requires the direct-runtime comparison to fail at the cutoff, and restores the original source in a finally block. Run both from the worktree root; `cargo test --manifest-path engine/law/Cargo.toml` runs all law tests against the stored oracle. The oracle file is regenerated by the first command.

The probes use Unsafe allocation and no world/tick. They override the three input predicates for same-vehicle, vehicle and pushable; noPhysics is set directly. Thus predicate provenance and virtual subclass dispatch are not tested by this runtime corpus. Position, initial velocity, and flags are corpus inputs; Mojang code executes the pair arithmetic and velocity additions. The guard cross-product includes impossible real-world combinations as independent supplied values. This is not an end-to-end server test.

Staged bytecode inspection: `Player.aiStep` delegates to `Avatar.aiStep` (inherited from `LivingEntity`); the living phase performs travel and block effects before `pushEntities`, with auto-spin checks immediately before the call. `ServerPlayer.pushEntities` delegates only when `tickRateManager.runsNormally()`. Living `pushEntities` gets the ordered `Level.getPushableEntities(this, this.boundingBox)` list, applies its cramming logic, then calls `doPush` for each neighbor. `doPush` dispatches `neighbor.push(this)`, so the neighbor is the pair-law caller. `LivingEntity.push(Entity)` returns while the caller sleeps, otherwise delegates to the base law; player classes do not override this pair method. Other entity subclasses may override it.

The eventual world integration must produce the vanilla tick ordering, exact ordered query results and their predicates at the phase, current per-entity positions/velocities, vehicle relationship, sleeping/virtual dispatch and server tick-rate state. It must apply the resulting velocities immediately before the next ordered pair; cramming and other subclass behavior are outside this function. The recorder does not yet supply those per-tick facts or their provenance; no wiring is claimed. Base `push(double,double,double)` additionally sets `needsSync` when it applies a finite impulse, which this velocity-only law does not model.
