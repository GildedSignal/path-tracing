# The law on Minecraft 26.3

The Fermi floor is one registry extraction per release and zero version lookup per ordinary tick. The captures compare 2,924 class paths by method descriptor and resolved bytecode, omitting debug tables and stack maps. The two client jars contain the common Mojang classes. The server uses the exact inner jar from Mojang's bundle. Before and after bytecode is in `D:\path-tracing-evidence\law-26.3\bytecode\`, indexed by `bytecode-summary.txt`. [Mojang 26.3 notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)

| Jar rule | Observed change and scope |
|---|---|
| Chunk palette NBT | 5023 writes default-state strings and `id`/`properties` compounds. Mixed lists wrap strings under the empty key. `region.rs` and `nbt.rs` decode both formats into the same state type and retain the per-chunk DataVersion check. |
| `ThrownEnderpearl.onHit` | The server-player transition keeps `Relative.ROTATION` and drops `Relative.DELTA`. The other owner branch passes `Vec3.ZERO` in place of its prior velocity. Both aim at `oldPosition()`. `pearl.rs` and the simulator apply the selected landing momentum. `PearlMomentum.java` executes the transition's arithmetic on both jars. |
| `FlowingFluid.canHoldAnyFluid` | The direct `LiquidBlockContainer` admission remains first. All other blocks switch from `blocksMotion()` plus class, tag and block exclusions to `WASHED_AWAY_BY_FLUIDS`. `ModelTable.java` generates the membership and water-container answer. `sim.rs` reads those facts in 5023. `canHoldSpecificFluid` still delegates to `canPlaceLiquid` for a container. The extractor verifies that all of the vanilla containers reject lava. The 4903 simulator uses its existing coarse admission. `structure_void` is an example the jar explicitly refuses. |
| `FlowingFluid.getFlow`, `getNewLiquid` | Only `getFlow` switches the empty neighbor's motion test to `BLOCKS_FLUID_FLOW` (`#blocks_motion` and `#all_signs` in the shipped pack). The registry and live recorder feed that answer into the current generator. `getNewLiquid` still reads `isSolid()` under the cell for source conversion. The 5023 simulator reads that getter separately from the tag. The sampled oak-sign gutter blocks current and the air gutter gives `(1, 0, 0)` on both jars. |
| `FlowingFluid.spreadTo`, `tick`, `LavaFluid.spreadTo` | The writes use `LevelWriter.setBlockAndUpdate`. Executing its default method calls `setBlock` with flags `3` and recursion limit `512`. This is the same route as the older three-argument writes. The law already writes with `update_flags::ALL = 3`. The existing simulator approximates face occlusion in fluid wall traversal. |
| `LavaFluid.randomTick` | The neighbor's fire-spread test uses `BLOCKS_LAVA_FIRE_SPREAD`, whose vanilla tag contains `#blocks_motion`. This branch ignites blocks during random ticks. The simulator models scheduled fluid ticks and the player's lava contact. Lava's random ignition of terrain is outside that boundary. |
| `LivingEntity.travelInFluid` | The post-travel float call now uses `ENTITY_FLOATABLE` after either liquid travel branch. In vanilla that tag resolves to water. The gate requires a vehicle in `CAN_FLOAT_WHILE_RIDDEN` and depth strictly greater than its fluid jump threshold. The vertical add remains the widened `0.04f` (`0.03999999910593033d`). `camel_husk` joins the mount tag. A separate client change skips push-out on passengers. The player tick already refuses ridden travel at `LivingEntity.travelRidden`. The ordinary water/lava travel recurrence requires no version branch for this change. |
| `Entity.collide` | 26.3 inflates the entity-collision search upward by `f64(maxUpStep())` after the usual expansion by requested movement. This changes which entity shapes the two sweeps can see near a step. `basis/sweep.rs` asks `World::visit_collisions` for block shapes. Its block query and step arithmetic are outside the changed entity query. Crowded step-ups with entity shapes require a separate witness and world input. |
| `Block.fallOn`, `BedBlock`, `AbstractBedBlock`, `StrawBedBlock` | `Block.fallOn` now multiplies distance by `(double)(1.0f - getFallDistanceReduction())` before damage. The white bed's former `fallOn` override did the same multiplication by `0.5d`. The extractors read the 5023 getter and encode the existing half-distance bit, leaving `core.rs` arithmetic intact. The jar gives the white bed a `9/16` shape height, `0.75f` restitution and `0.5f` reduction in both versions. Straw is `1/4` high at its default foot state, with `0` restitution and `0` reduction. The generator reads both halves and all orientations from the jar. |
| `AbstractBedBlock.useWithoutItem`, `StrawBedBlock.destroyOnLeave` | Common bed use and placement move to `AbstractBedBlock`. Straw uses `STRAW_BED_RULE`, whose default sleeps when dark, sets no spawn and destroys the bed on leave. Destruction replaces the cell with air via `setBlockAndUpdate`. Its sleep height requires a matching foot when starting from the head. `player.rs` has bed-rule and respawn helpers but no sleep lifecycle or straw-bed action. Sleeping in or restoring straw beds remains outside the certified actions. Traversal uses the generated collision and landing answers. |
| `LivingEntity.hurtServer`, `Entity.commonTick` | The damage window still writes `20`, compares against `10`, and keeps `lastHurt` for the difference. Its field is now `LivingEntity.damageCooldownTime`. `Entity.invulnerableTime` is a separate temporary immunity timer. A jar probe with `(cooldown, immunity) = (20, 0)` gives `false` from `isTemporarilyInvulnerable()`, while `(0, 4)` gives `true`. Bot capture, player snapshot and the server wire send the damage cooldown. The ordinary damage-window recurrence is unchanged. The general immunity gate now calls `isInvulnerable()` instead of reading the old permanent boolean. Default knockback skips `NO_KNOCKBACK` sources in both versions. In 26.3 it also skips a blocked hit with damage remaining `<= 0.0f`. The ordinary resource ledger does not certify temporary immunity or shield-contact outcomes. |
| `NetherPortalBlock.getExitPortal` | The existing-POI branch precedes the spectator test. With no POI, the jar called `createPortal` once for both modes in 26.2. In 26.3 it called once for an ordinary entity and zero times for a spectator, returning null for the latter. `portal::nether_exit` applies that gate around the same search result and creator. The End gateway and End portal block diffs remove codec setup only. The general portal tick delegates the existing destination checks to `teleportToPortalDestination`. Live dimension changes remain outside the ordinary block-contact tick. |
| `PistonBaseBlock.isPushable`, `PushReaction` | The new enums are reordered. The actual switch maps `IMMOVEABLE` to false, `POPPED` to the `destroy` argument and `PUSH` to equality of the movement and piston directions. `PUSH_PULL` follows ordinary movement, and `IGNORE_ENTITY` skips entity push. The Rust table decodes names to the five existing reactions and keeps the same piston witnesses. |
| Shulker boxes | The instruction streams for `getShape`, `getStateForPlacement` and `canOpen` match. The 26.2 Vibe witness shows a full cube when closed and extension along `FACING` when open. The 26.3 palette by itself carries no lid progress, so the shape remains refused in `ModelTable.java`. |
| Mod descriptors and loader | The bot uses the matching hurt clock, swing, chunk and item-drop signatures. The server uses the matching teleport acknowledgement, position/velocity messages and tracking interval type. The graphics migration moves the optional swarm renderer's Blaze3D API to RenderPearl. SDL3 and the exact client libraries are launcher inputs. [Fabric 26.3 notes](https://www.fabricmc.net/2026/09/15/263.html) |

`FoodConstants`, `FoodData`, `Attributes` and the modeled hunger, healing, saturation and wither effect bodies have identical instruction streams. `DamageType` changes its codec. The changed client spinning and underwater sound paths feed rendering and audio. Registry codec setup, Realms invites, translations, the debug overlay and management log formatting have no readers in the law.

The registry export also covers poplar, shelf mushrooms, shrubs, straw-bed states and the wool and concrete steps. Cushions are entities. The block table gives no cushion-contact certificate. `Block.dropFromBlockInteractLootTable` gains the interaction position for the loot context. `Block.popResource` has no changed overload in the comparison. The kit's track gate still excludes missions whose restoration needs item-drop pickup. The change to item-driven block transformations does not add a new kit action.

`JarBoundaries.java` runs the selected jar against in-memory getters and a missing-portal probe. It produces `engine/world/tests/fixtures/jar-boundaries.tsv`. The file records the two fluid courses, both bed data sets, the actual write flags, portal creation attempts and the independent damage clocks.
