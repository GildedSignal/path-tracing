# Swarm 0 — scripted headless server workload

Goal: measure the server with 100 headless bots and exercise the normal authoritative movement path. Keep it on a disposable rig. Prefer one server-side adapter with the existing law and world read interfaces, and small per-bot state. Reuse a view of the loaded world across bots. Expose authoritative tick stamps and changes from the adapter so later planning can attach dependencies. Keep the first controls scripted and comparable to vanilla captures.

Before running the matrix, freeze one seed, starting states and inputs for idle, dispersed movement and dense movement. Run zero, one and 100 headless bots on the same machine at stock speed. Keep a separate accelerated server run so population and requested rate can be changed independently. Report actual TPS, tick-time distribution, shared world and per-bot memory, work spent on tracking and collision, and movement corrections. Use the same workload at stock speed for checks on accelerated behavior. Compare an individual bot with a vanilla replay before trusting the population run. Record the authoritative states and packet or movement outcomes that distinguish legal movement from a teleport. Keep server profiling separate from the parity run if it materially changes the result.

Acceptance for the population rung is 100 simultaneously active, server-visible, headless bots completing the scripted run at stock speed with correct controls and outcomes, including the dense case. Include an injected bad movement as a negative control. After the independent speed and population rungs, measure the combined load. Do not choose a pathfinder, implement worldtube certificates, or assume a shared summary stays compact.
