# Lens: the generative function of a jump (find the function, then see where it solves)

**Why it matters.** Julien (12 November, S90): "we should not learn jumps but classes of jumps and uncover the generative function otherwise it'll get expensive ... maybe you find a function and you see where it solves things? ... if we can find generative functions then we're winning." And: "you think in 3D not in 4D." The law's free motion is one small rule per tick (`engine/law/src/movement.rs`, `travel_air`, lines 415 to 440): add an input vector whose size depends on on-ground, sprinting and the friction of the block below, move, then multiply the velocity by friction × drag and apply gravity. The class's yes-or-no facts choose which rule applies; keys and yaw choose the direction of the added vector. If that is the whole of it between events, a word is one rule applied k times, the set of places a jump can reach is computable without search, and a class of jumps is simply the region of puzzles one function solves. Lanes `gait-modulo` and `arc-certificate` (both reproduced) already showed gaits and free arcs are exact arithmetic.

**Inputs.** `engine/law/src/movement.rs` (the rule and its neighbours: `friction_speed`, `flying_speed`, `input_vector`, the jump impulse, the 0.003 thresholds), `engine/words` (programs, events), his 18 tracks in `engine/world/tests/fixtures/`, `lab/wiki/gait-modulo.md`, `lab/wiki/arc-certificate.md`, `lab/wiki/speed-of-light.md`.

**The question.**
1. **The family.** From the law's source, list every per-tick velocity rule a walking, sprinting, sneaking or jumping player can be under, as: the facts that select it (name each state field or block property), the multiplier, the added vector as a function of keys and yaw, and the thresholds. How many distinct rules do the walks on his tracks actually use?
2. **Prediction without the law's tick.** For stretches with no event, predict k ticks ahead from the rule alone, with the law's own float operations and no world read. Compare bit for bit with the law over every such stretch of the walks. Report agreements, and each disagreement with its cause.
3. **The run-up.** From rest, and from each landing state the walks produce, the velocity and displacement after k ticks of each program: is the takeoff state a function of (start velocity, program, k, the block's friction) alone? Tabulate it. Momentum carries across jumps: show the landing state of one jump as the start of the next.
4. **Where it solves.** For a takeoff box and a target box, compute from the tables, by arithmetic and geometry only, every (run-up program, ticks, aim, air program) whose arc lands on the target. Every cell the body passes carries its tick: the tube is in space and time. Give two envelopes per height change from −3 to +1.25 blocks: the inner one (the furthest gap the 54 programs reach) and the outer one (the furthest gap if the aim were free on every tick: a bound no input sequence can beat; say how float rounding and the sine table bound the difference).
5. **His tracks, classified.** For each jump on a route to B: inside the inner envelope (solved by lookup: report time per query and verify by a replay in the law), between the two (possible, not yet known: the zone to learn in), or outside the outer (impossible as posed: another mechanic is needed). Counts per track. Check "outside" on a sample by exhaustive search at small depth.
6. **Where the function is not enough.** List the events on his tracks that need the world (walls, ceilings, ladders, slime, ice, fluids, edges while sneaking), with counts. For each: is it another rule of the same family, or a clamp on position?
7. **A world that moves.** A platform that exists only on a known set of ticks: show that the same lookup works when the tube's cells carry their ticks, using arithmetic plus one replay through a world wrapper that implements the schedule. Report the lookup time against the static case.
